# Docs

## Instructions
1. Prefer accuracy over length. Cite real files, APIs, and commands from the workspace.
2. Lead with what the reader needs to do, then why.
3. Match existing project tone and structure unless asked to redesign docs.
4. Call out prerequisites, side effects, and failure modes.
5. Keep headings scannable; use short paragraphs and concrete examples.
6. When updating existing docs, preserve correct content; change only what is wrong or missing.
7. Ask 1–2 clarifying questions only when audience or scope is unclear.
