# AGENTS.md

## Repo shape

- Electron desktop coding agent ("Agent V"): electron-vite + React 19 + strict TS + Tailwind 4, pnpm workspace. Node >= 22.18; pnpm version pinned via `packageManager`.
- Git repo root is this folder. If a session opens one level up (`Documents\VYOTIQ - AGENT V`), that parent is only a wrapper containing this same-named folder.
- Workspace packages: root Electron app + `landing/` (Astro site, `@vyotiq/landing`; use `pnpm landing:dev` / `pnpm landing:build`).
- Process boundaries are eslint-enforced (`no-restricted-imports`): renderer must not import `@main/*`; main/preload must not import `@renderer/*`. Aliases: `@shared` -> `src/shared`, `@main` -> `src/main`, `@renderer` -> `src/renderer/src`.

## Documentation is stored as Word binaries

- Most long-form references ship as binary Word `.docx` copies (e.g. `docs/reference/2026-jun-aug/*.md.docx`, `resources/harness/default.md.docx`, marketplace `SKILL.md` files). Repo-level guidance that is NOT a docx copy still lives as plain `.md`: `AGENTS.md`, `README.md`, `.cursorrules`, and the canonical harness `resources/harness/default.md`. Don't assume every doc is a docx.
- To read any of them: a docx is a zip; extract `word/document.xml`, strip tags. PowerShell:

  ```powershell
  Add-Type -AssemblyName System.IO.Compression.FileSystem
  $zip = [IO.Compression.ZipFile]::OpenRead("$PWD\<file>.md.docx")
  $r = [IO.StreamReader]::new($zip.GetEntry('word/document.xml').Open())
  ($r.ReadToEnd() -replace '<w:p [^>]*>|<w:p>', "`n" -replace '<[^>]+>', '')
  $zip.Dispose()
  ```

- Deep architecture reference: `docs/reference/2026-jun-aug/15-architecture.md.docx`.

## Commands

- Verify before finishing: `pnpm typecheck && pnpm test && pnpm lint` (CI runs typecheck, test, lint, then builds).
- Single test file: `pnpm exec vitest run tests/main/unit/<name>.test.ts`
- `pnpm build` = typecheck + icon/wasm sync + electron-vite build -> `out/`. `pnpm dev` runs sync scripts first (HMR); `pnpm start` previews the built app.
- `pnpm test:e2e` = Vitest over `tests/main/e2e` (mocked agent pipeline). Not the same as `pnpm test:gui-e2e` = Playwright driving the real built app (`out/main/index.js`) — needs a prior `pnpm build`, runs serially (1 worker), and CI sets `VYOTIQ_E2E_FIXTURE=1`.
- CI also gates on `pnpm audit --audit-level high`, an unpacked `electron-builder ... dir` smoke package, and `pnpm landing:build`.

## Test quirks

- Vitest `globals: false`: import `describe`/`it`/`expect` from `'vitest'`. Default environment is node; DOM tests opt in per file with `/** @vitest-environment jsdom */`.
- `tests/setup.ts` stubs localStorage/matchMedia, mocks xterm, makes `createWindow` throw, and calls Testing Library `cleanup()` manually after each test.
- Renderer tests fake the preload bridge as `window.vyotiq`.

## Generated assets & tool registry

- Do not hand-edit synced outputs: `src/renderer/public/file-icons/**` (copied from material-icon-theme), wasm under `resources/codeindex/wasm/`, brand/app icons — regenerated by `scripts/sync-*.mjs` on postinstall/dev/build.
- Adding/changing a built-in tool means updating argument schema, handler, and runtime limits/classification together. `tests/main/unit/toolsSchema.test.ts` enforces registry **schema/description + 59-tool count** parity, and also asserts at runtime that every `TOOL_REGISTRY` key has a wired, non-stub `BUILTIN_HANDLERS` entry. Handler *existence* parity is additionally guaranteed at compile time by the `Record<AgentToolName, ToolHandler>` type in `src/main/agent/tools/index.ts` (a missing handler is a type error). Tool descriptions stay short capability blurbs in `src/main/agent/schemas/tools.ts`; the behavioral harness lives separately in `resources/harness/default.md.docx` (a workspace-local copy takes precedence at runtime).

## Runtime state

- App state/logs live under `%APPDATA%/vyotiq/` (userData), never in the project folder. Project-local agent memory is `{workspace}/.vyotiq/memory/`. Session files: `messages.jsonl` is the canonical chat transcript; `events.jsonl` is append-only ops telemetry.
- Sentry DSNs are baked in at build time via `define` in `electron.vite.config.ts` (runtime env is empty in packaged builds); set locally via gitignored `.env`.

## Windows dev gotchas

- From IDE-integrated shells, clear `ELECTRON_RUN_AS_NODE` before `pnpm dev` / `pnpm start` (`Remove-Item Env:ELECTRON_RUN_AS_NODE`), or Electron boots as plain Node and crashes with `Cannot read properties of undefined (reading 'isPackaged')`.
- Killed dev shells orphan `electron.exe` holding the Vite port; kill it before relaunching or new windows render blank.
- `node-pty` is optional: prebuilds usually work — don't force `npm_config_build_from_source` (source rebuild needs VS Build Tools with Spectre-mitigated libs). A pipe-shell fallback runs when PTY is unavailable.

## Existing agent rules (still in force)

- `.cursorrules` + `.cursor/rules/*.mdc`: evidence-based minimal changes; plan/ask before ambiguous architecture-harness-product work; ship only fully wired UI (no placeholder controls; removing a feature removes its settings/copy in the same change); never restore deleted files from git history — fix forward instead.
- `.mcp.json` wires a Code Context Engine MCP (`context_search`, `expand_chunk`, `related_context`, `session_recall`). The bundled config resolves `cce` from `PATH` and passes a relative `--project-dir .`; adjust the command/project-dir to your environment. If `cce` is absent the app degrades gracefully (startup `.catch` + circuit breaker) and the four tools simply won't appear.
- `.gitignore` uses a root-anchored `/renderer/` pattern, so files under `src/renderer/` are NOT affected (the pattern only matches a top-level `renderer/` dir, which does not exist). The real risk is `*.docx` (line 17): newly added documentation `.docx` (and root-level `*.md.docx` duplicates) can be silently ignored by git — force-add doc additions.
