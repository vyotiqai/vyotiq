# PR description

## Instructions
1. Summarize the problem and approach in a few bullets.
2. Call out risk areas, migrations, and user-visible behavior changes.
3. Include a concrete test plan reviewers can follow.
4. Link related issues or prior context when known.
5. Match the repo's PR template if one exists; otherwise use Summary + Test plan.
6. Do not pad with filler or restate the entire diff.
